# PolishTreasuryBondsData

Small, auditable and deterministic data source for Polish retail Treasury Bonds.

The repository is designed primarily for consumers such as Inspector Budget that need to calculate holdings offline from a previously downloaded immutable dataset.

## Supported public contract

Use GitHub Pages:

```text
/v1/latest.json
/v1/status.json
/v1/snapshots/<datasetRevision>/manifest.json
/v1/snapshots/<datasetRevision>/catalog.json
/v1/snapshots/<datasetRevision>/product-definitions.json
/v1/snapshots/<datasetRevision>/gus-cpi.json
/v1/snapshots/<datasetRevision>/nbp-reference-rates.json
```

`latest.json` is the small mutable pointer. The snapshot it selects is immutable and can be cached permanently.

`status.json` reports source freshness for the currently available dataset. Availability of Pages is not required to reopen a portfolio if the consumer already has a valid snapshot locally.

## Repository model

```text
data/
  products/        canonical product rules
  series/          canonical series terms and corrections
  reference/       canonical GUS and NBP facts
  sources/         content-addressed official evidence
  source-status.json

publication/v1/
  latest.json
  status.json
  snapshots/<datasetRevision>/

dist/
  catalog-v1.json
  reference-data-v1.json
  metadata.json
```

`dist/` is frozen legacy v1 only. There is deliberately no active v2 build layer in `dist/`; v2 documents are built directly into immutable publication snapshots.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the trust model, sources of truth and invariants.

## Official sources

The updater accepts data only from the configured official acquisition endpoints:

- Ministry of Finance / gov.pl for the retail-bond XLS workbook;
- the official Treasury Bond offer pages for an independent current-offer cross-check;
- GUS SDP API for CPI;
- NBP official XML for the reference-rate timeline.

Transport policy is intentionally implemented in the source adapters, not frozen into the public JSON Schema. A historical document remains valid if an institution later moves an official endpoint.

## Provenance

### Ministry of Finance

Every published series revision points to a SHA-256-addressed XLS stored under `data/sources/mf/`, including the workbook sheet and source row. Tests reconstruct financial values from that evidence.

### GUS

New refreshes save exact official response bodies under `data/sources/gus/`. A content-addressed manifest binds the request URLs to the exact response hashes used to normalize CPI facts.

### NBP

New refreshes save exact official archive and current-rate XML under `data/sources/nbp/` and bind both SHA-256 hashes into provenance.

Historical GUS/NBP evidence is never fabricated retroactively.

## Corrections and history

Published canonical facts are append-only:

- changed series terms create the next `termsRevision`;
- corrected GUS observations create the next `revision` for that period;
- corrected NBP observations create the next `revision` for that effective date.

Existing immutable snapshots are never rewritten. `latest.json` advances to a new complete snapshot after review.

## Update flow

```text
official sources
  → raw evidence
  → parser / cross-check / semantic validation
  → canonical facts
  → deterministic snapshot
  → updater PR
  → required Validate data check
  → reviewed main
  → GitHub Pages
  → public smoke test
```

The automated updater does not publish production directly. Pages deploys only approved `main`.

## Local validation

Python dependencies are fully pinned and hash locked.

```bash
python -m pip install --require-hashes -r requirements.txt
python -m unittest discover -s tests -v
python scripts/check_immutable_snapshots.py
python scripts/update.py --offline --check
```

A live refresh can be run explicitly with:

```bash
python scripts/update.py
```

Live refresh is fail-closed and transactional. Source disagreement, missing coverage, unsafe redirect, malformed input or validation failure prevents the candidate financial data from being published.

## Legacy v1

The original `dist/catalog-v1.json`, `dist/reference-data-v1.json` and `dist/metadata.json` remain frozen byte-for-byte for compatibility and audit purposes. They are not regenerated by the current pipeline.
